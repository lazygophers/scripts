能不能写一个 mail 工具

2026-09-10 · 调研对象：多账号收发邮件的命令行工具 · 证据：各邮箱服务商官方文档 + docs.python.org + 本仓库源码
能做，而且不用装任何东西
Python 自带的 imaplib（收信）、smtplib（发信）、email（解析邮件）就够了，零第三方依赖。
难的不是写代码，是登录。各大邮箱这两年陆续关掉了「邮箱地址 + 密码」这条路。

你的三条需求，逐条对答

1同时登录多个邮箱，自动管理收发

能做 每个邮箱一条连接，用完就断。
一个限制 Gmail 规定同一账号最多 15 个客户端同时连着（官方说明）。如果工具每跑一次就新建连接又不回收，长期会撞墙。其他家的上限没查到。

2登录信息用现有的密钥存储格式，按 email 分开存

能做 但有个前提问题
这套格式在 lib/archery.py:59-178，已经在跑了：先写临时文件再原子换名（别人读不到写一半的）、flock 跨进程锁、权限 0600。

问题是：这套代码已经被抄过一遍了。lib/grafana.py:26-115 是它的逐行复制，只有异常类名和报错里的命令名不同。mail 会是第三份。

3只有一个就用它，有多个就要指定

已经写好了
lib/archery.py:147-168 的 resolve_profile() 干的正好是这件事——指定优先，其次默认账号，只有一个就直接用，多个又没指定就报错并告诉你下一步敲什么。
改成按 email 存，只需把「URL 转域名」换成「email 转小写」。这条需求的工作量接近于零。

另外两个必须知道的坑

SSL 默认不验证对方是谁

Python 官方文档原话：用默认设置时「连接是加密的，但不校验服务器证书和主机名」。

意思是：加了密，但不确认对面到底是不是真的 Gmail。中间人可以直接冒充。

这一行不能省： 
ssl_context=ssl.create_default_context()

imaplib 给的是协议原语，不是邮件

它返回一堆半解析的字节，UID、附件结构、中文文件夹名全要自己解析。这是最容易写出 bug 的地方。

绕过去的写法：只用 imaplib 干两件事——搜出 UID、把整封原始邮件拉下来；所有解析交给 email 模块。最难啃的那块直接跳过。

代价：带大附件的邮件会被整封下载。

建议怎么做

第一版：只支持应用专用密码 / 授权码，纯标准库，不支持 Outlook.com。

覆盖 Gmail、iCloud、QQ、163、Fastmail、Zoho——够日常用了。零依赖，几百行。
把「怎么认证」抽成一个函数（不是一个类，就一个函数），以后真要加 Outlook 的 OAuth2，改动只落在那一个函数里。
如果 IMAP 那层写到 200 行还在跟协议搏斗，就换 imap_tools。

ikvk/imap_tools，842 stars，最近发版 2026-08-06，零外部依赖，自带 OAuth2 认证方法。
它同时替掉「协议解析」和「邮件树遍历」两块，一个循环直接拿到解析好的邮件对象。

另外两个候选不推荐：IMAPClient 只省一半（不解析正文），aiosmtplib 这个场景用不上。

要你拍板的四件事

1工具叫什么名字

不能叫 mail： 
$ which mail mailx sendmail
/usr/bin/mail
/usr/bin/mailx
/usr/sbin/sendmail
macOS 自带 /usr/bin/mail，而本仓库的 bin/ 在 PATH 里排在系统目录前面——叫 mail 会把系统那个盖掉。这也正是当初 ovpn 不敢叫 openvpn 的原因。

2要不要顺手把重复的密钥存储抽出来

现在 archery 和 grafana 各存了一份一模一样的代码，mail 会是第三份。
抽成一个 lib/profile_store.py，三个工具共用，参数只有两个：配置文件叫什么、key 怎么规范化。
这才是「保持同一格式」在代码层面唯一说得通的做法——否则三份会各自漂移。

3要支持哪几家邮箱

你实际在用哪些？这直接决定要不要写 OAuth2 那一整套（注册 app、本地回调端口、token 刷新）。
只要清单里没有 Outlook.com / Hotmail / Live，就都不用写。

4要做到什么程度

只发信？还是收信也要（列邮件、读正文、下附件、搜索、标已读）？
只发信的话，工作量是收发都要的三分之一不到。

还没查实的五件事

需要: QQ 邮箱的服务器地址端口，官方页面抓不到原文——`webgrab`（含 `--render`）抓了 4 个页面都只返回导航、正文为空（页面是 JS 动态渲染的），WebFetch 对该域直接拒绝。现有数字来自搜索摘要。写代码时用 openssl s_client -connect imap.qq.com:993 自己验一次更快。
需要: 163/126 免费版邮箱的 IMAP 端口没有现行官方原文。抓到的是 VIP 版参数页和一个 2007 年的老页面。推测: imap.163.com:993 / smtp.163.com:465。
需要: Proton Bridge 的本地地址端口。已确认 Bridge 必需、仅付费、仅桌面；端口由 Bridge 装完自己分配，文档里未必有固定答案。官方那页返回 404。
需要: 没找到一份官方明说「Gmail 应用专用密码 2026 年仍可用于 IMAP」的声明。两条间接证据都指向仍可用。写代码时必须把「认证失败」当成正常分支处理，给出人话错误信息。
需要: 并发连接上限只查到 Gmail（15 个）。QQ / 163 / iCloud / Fastmail 的未知。
