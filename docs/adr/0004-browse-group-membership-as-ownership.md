# 0004. browse 的归属真源是组成员身份，不是记录的 tabId 集合

- 状态：已接受（2026-09-28）
- 范围：browser-extension/browse、lib/cli/browse.py

## 背景

browse（命令行驱动浏览器扩展）需要「只允许操作/读取自己创建的页面」的硬边界。
两种候选真源：

1. **tabId 集合**：扩展里记一份「我开过的 tabId」，命令查表。
2. **组成员身份**：自己开/收编的页面收进一个专属组，「在这个组里」就是自己的。

## 决策

选**组成员身份**。专属窗口 + 单组（`browse`，蓝色）；用户拖标签进组即接管、拖出即放
走；`lg:tabs.adopt` 显式收编并过确认策略。持久层只存 URL 登记表（origin+path，LRU 50），
用于浏览器重启后按 URL 认领回组——组 id 本身不跨重启。

## 后果

- 授权/撤权对用户是**物理手势**（拖动标签），不需要任何命令；代价是权限跟着用户手滑走。
- `chrome.tabGroups` 没有成员变更事件，监听拖拽不可靠——判定一律懒做：命令到达时现场查
  `tab.groupId`，零监听、永不漂移。
- 排除了「程序内表格当真源」后，登记表降级为纯认领辅助，坏了不影响权限判定。
- 官方（Claude in Chrome）同构选择（tab group tied to session + 拖入组接管）佐证了这条
  路线的可用性；差异在于我们另加了独立窗口与重启认领。

## 落选方案

tabId 集合真源：更「程序正确」，但用户随手拖动标签不会更新表格，出现「拖一下标签页
就与权限状态不符」的怪象；且要另做一套授权 UI。在「用户是唯一授权人」的前提下劣于
组成员身份。
