# 排障：误报、对照、版本漂移

2026-10-08 push_canary 三层故障（假文案 → 脏 go.mod 挡 checkout → grpc/Go 版本不兼容）
复盘出来的。三层是同一条链：每层的报错都指向了别处。

## 包装命令的报错必须透传原文

子进程 `capture_output=True` 失败时，包装层不得把推断写成原因。
`lib/git.py` 的 `_switch_to_branch` 曾把「go.mod 未提交挡 checkout」吞成
「请确认分支 'canary' 是否存在」，排查方向被假文案带偏。规则：
**报错 = 原文 + 可选上下文提示，没有原文就没有报错。**
改这类文案前先写复现测试（本次 commit 0c3c159 的路径）。

## 「时过境迁才炸」先做同环境 A/B

同一目录、同一份代码，只换一个变量（工具链版本、依赖版本、解释器）各跑一次。
一次对照胜过读文档猜机制。本次 go1.26.8 过 / 1.27.1 挂的同目录对照是决定性一步，
随后 `go mod graph` + `IgnoredGoFiles` 实测坐实 x/net v0.54 排除旧 http2 实现。

## 版本管理器里的 `latest` 是时间炸弹

mise `go = "latest"`：升级后行为静默改变，同目录两个版本结果不同；而且触发点
可以远在别处——本次是 10-04 改过 mise 配置，三天后才在别的仓库炸出来。
新配置钉固定版本；浮动版本出问题时先查「最近改过什么配置」，再查代码。
